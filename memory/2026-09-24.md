# 2026-09-24

## Observability fixes in serve-dashboard.py / dashboard.html

Context: dashboard on port 37778 (pm2 app `cc-sesh-master`, PID binds
`127.0.0.1`). Process Monitor was dead on Windows and the Session Viewer
event cursor could loop.

Fixes applied:

- `collect_status` split per platform: Windows now uses a PowerShell CIM
  collector (`Win32_Process` + `Win32_PerfFormattedData_PerfProc_Process` +
  `Win32_PageFileUsage`) and ctypes `kernel32.GlobalMemoryStatusEx` for
  system memory. Result cached 1.5s (`_WIN_STATUS_CACHE`). Note:
  `GlobalMemoryStatusEx` lives in `kernel32`, NOT `psapi` on this box.
- Server switched to `ThreadingMixIn` (`daemon_threads=True`) so slow
  content-search (ripgrep, 10s timeout) no longer blocks /status polling.
- `_SKIP_TYPES` now drops Claude Code metadata lines that carry no uuid
  (`attachment`, `last-prompt`, `atis-latch`, `mode`, `permission-mode`,
  `ai-title`, `custom-title`, `agent-name`, `pr-link`, `bridge-session`,
  `file-history-delta`, `cost-state`). They were 4k+ lines across the
  local corpus, drained the event limit, and their empty uuid broke the
  `?after=` cursor (tail refetched every poll).
- `dashboard.html` `pollNewEvents`: ephemeral-subagent early return moved
  BEFORE `pollNewEventsBusy = true` (busy flag leaked, killing polling
  permanently after viewing an inline subagent); cursor now only advances
  over events that have a uuid.
- Codex/Kimi tail reads: newline counting before the tail offset cached
  per (path, size, mtime) in `_line_offset_cache` (`_count_lines_before`);
  Kimi no longer fabricates line numbers via `/200` estimate.
- Query param ints guarded (`_qint`): `?offset=abc` etc. no longer 500.

Also this morning: Claude session titles (`customTitle` > `aiTitle` >
`agentName`) extracted from first 64 JSONL lines with explicit
`encoding='utf-8'` (accent corruption before).
